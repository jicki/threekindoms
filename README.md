# Three Kingdoms HD-2D（三国 HD-2D）

一款回合制三国战略游戏的 HD-2D 重制：像素角色立在 3D 地形上，加上实时光影、景深与后期。玩法规则和数值参照 1992 年 FC 游戏《三國志II 覇王の大陸》。游戏用浏览器运行（three.js），也能打包成 Electron 桌面版。

> 本项目是非官方、非商业的同人重制，与 Bandai Namco 无关。仓库不包含原版 ROM，但包含原版和 PS 复刻版音乐及部分音效。立绘等美术由 AI 生成，经人工筛选与修改。

## 项目结构

```
hd2d-mvp/
  index.html          游戏入口
  save-editor.html    存档（记录）编辑器
  vignettes.html      命令演出预览页
  src/
    core/             规则层，不依赖渲染：
                        game.js 战略层与全部命令、ai.js 战略 AI、warcore.js 开战与战后写回、
                        field.js 战争地图、tactical.js 白兵、skirmish.js 白兵与单挑结算、
                        saveedit.js 记录编辑、ahuinan.js 阿会喃漏洞模式
    war/              战争地图 3D 视图（board、units、overlay、camera、pick、interact、play、probe）
    *.js              three.js 场景（strategy*.js 战略地图、warview.js 战场、tacticalview.js 白兵、
                      duelview.js 单挑等）与流程、界面（app.js、ui.js、ui.css）
  data/
    game-data.json    武将、城市、地图、事件等全部规则数据
    thanks.txt        片尾鸣谢名单
  assets/             美术、3D 模型与音效（素材包，见下文）；manifest.json 列出可选资源
  tests/              测试（*.test.mjs），公共辅助函数在 game.mjs
  tools/              开发服务器、无头浏览器、截图与检查、模拟，以及美术切图与烘焙脚本
  desktop/            Electron 打包脚本
```

## 获取代码与素材

仓库包含代码、数据、已收录的音乐与音效，以及内置角色的美术素材。原有美术、3D 模型、其他音效和图标放在 [Releases](https://github.com/tianlin/threekindoms/releases) 的素材包 `threekindoms-assets-<版本>.zip` 里。

```bash
git clone https://github.com/tianlin/threekindoms.git
cd threekindoms
# 从 Releases 下载与代码对应的素材包（跟进 main 就用最新的），解压到仓库根目录：
unzip -o ~/Downloads/threekindoms-assets-0.3.6.zip
shasum -a 256 -c ASSETS.sha256 | grep -v ': OK$'    # 没有输出就说明素材齐全
```

素材包中的文件已经写进 `.gitignore`，解压后不会出现在 `git status` 里。根目录的 `ASSETS.sha256` 列出了素材包中文件的哈希：
- 解压后如果 git 显示 `ASSETS.sha256` 被修改，说明素材包和代码版本不一致，请换用对应版本的素材包。
- 缺少素材时，开发服务器、`tests/lfs-pointer.test.mjs` 和桌面版打包都会提示你先解压素材包。

## 运行

需要 Node.js 22 以上和 Python 3。

```bash
npm --prefix hd2d-mvp/desktop install     # 首次：安装 three.js、字体和 Electron
python3 hd2d-mvp/tools/serve.py 8677      # 启动开发服务器
```

然后用浏览器打开 http://localhost:8677/hd2d-mvp/ 。在网址后面加 `?mute` 可以静音。

### 战场操作

可点击武将所在格或姓名选择武将；画面拥挤或人物被遮挡时，使用战场右下角的「选将」从我军名单选择。布阵时也可以用此名单或手机上的 ‹、› 切换武将；电脑键盘使用 `[`、`]` 切换。正在选择攻击或计略时，先完成或取消该指令再使用名单切换。点击姓名会优先选中对应武将，若姓名挡住目的地，可按住 `T` 或点「地形」后选择地格。

### 战场生死

开局时或游戏中的「☰ 系统 → 战场生死」可选择原版规则或「不战死」，选择随本局存档保存。开启后，白兵、单挑和计略中体力归零的武将与君主会退出战场并被对方俘获；电脑之间的战争也将伤亡改为被俘。君主恢复体力至 30，但不超过其体力上限。

战败君主无路可退时优先由胜方俘获；俘获方没有可用位置时君主下野。君主被俘或下野后，原势力有部下时选择继承者，否则势力灭亡；总大将被俘仍会结束战斗。开启不战死不会阻止病逝，病逝由「武将不老」单独控制。单挑宝物仍须实际斩杀才能获得，被俘不会触发斩杀奖励。

### 背景音乐

游戏会自动检查本地可选音频。自带服务器会批量报告清单中可用的素材，减少启动时的逐项探测；静态托管或旧服务器自动回退到逐项检查。在标题页或游戏中的「☰ 系统 → 曲目」可以切换已提供的音乐版本，选择保存在当前浏览器中；浏览器可能要求先点击页面才能播放。没有可用音频时，部分场景使用合成音乐。已有的 `remix/` 素材仍显示为 Remix，不会误认为 PS 复刻版。

原版和 PS 复刻版音频放在 `hd2d-mvp/assets/audio/original/` 和 `hd2d-mvp/assets/audio/ps/`，文件名与 `assets/manifest.json` 中的对应场景一致。已收录的 16 首背景音乐、事件短曲、单挑音效，以及爆炎和碰撞音效随 Git 仓库提供，无需另行下载；其他本地音频仍被忽略。音频保留现有的 M4A 和 MP3 格式，避免对有损素材重复转码。构建 Docker 镜像或桌面版时会打包这些音频；加入或更换音频后需要重新构建。

目前接入的场景及音源对应关系如下。FC 音频来自 [原版 NSF 曲目表](https://www.zophar.net/music/nintendo-nes-nsf/sangokushi-2-haou-no-tairiku)，PS 曲目编号来自 [Namco Anthology 1 音源](https://downloads.khinsider.com/game-soundtracks/album/namco-anthology-1-ps1-gamerip-1998)，结合[场景曲目资料](https://w.atwiki.jp/gamemusicbest100/pages/5645.html)及旋律特征比对；结局使用 [PSF 音源](https://ftpmirror2.infania.net/sites/modland/incoming/warehouse/PSF/HaounoTairiku_psf/HaounoTairiku_ezp104_PSF/)中标注为 Epilogue 的曲目。PS 版战后和失败暂未找到可可靠对应的文件，选择 PS 版时会回退到该场景的其他可用版本。

其他内政命令沿用项目原有的短曲分组。白兵咒缚、挑发、强弩、士气向上和火矢使用各自的游戏内合成音效，在效果出现时播放，不中断战斗背景音乐；爆炎在爆点播放爆裂声，素材不可用时使用合成音。失败的战术使用失败提示音。地图计策沿用经过原版追踪的施计短曲，效果落地时按水、火、弩等视觉效果播放不同短音。这些新合成音效不是原版或 PS 原声。PS 短曲按音源、场景资料和旋律比对推断，部分资料的事件名称互相冲突；表中出阵与陷阱、灾害与要击分别使用相同的 PSF 曲目，尚未逐项对照原 PS 游戏画面。单挑的马蹄、挥击、牵制、攻击和舍身音效采用 FC 音效，两个音乐版本共用；攻击额外叠加短促的低频合成冲击，以便与牵制区分。白兵箭矢落地也使用 FC 音效。短曲结束后恢复场景背景音乐，所选版本的短曲无法读取时尝试其他可用版本；提前跳过计策演出时停止该演出启动的短曲并恢复背景音乐。

战场计策造成实际损兵时同步播放受击声；本身使用碰撞音的计策不会重复叠加，失败或零损兵不会额外播放受击声。白兵近战及箭矢落点播放碰撞音和落点音；关键音效文件加载过慢时先使用合成回退，加载完成后供后续动作使用，不会补播过期声音。

弓箭发射、失败提示、白兵移动步伐、号角、胜利、获得宝物及开场箭矢音效目前没有独立音频文件，使用游戏内合成音；收入和升级短曲不可用时也有合成兜底。战场地图上武将行军使用已有的原版马蹄素材，素材不可用或加载过慢时使用合成回退；白兵步兵和弓兵使用脚步声、骑兵和武将使用合成马蹄声。多队同时移动时限制音效叠加，并遵循音效音量设置。地图选城按原版习惯保持静音。

单挑的阵亡、被俘和败走使用不同结局演出；自定义动作缺少无骑手马匹素材时，不会把骑乘动作显示为空马离场。

没有独立演出的内置专属计策会选用与名称相符的既有计策画面和音效；管理员新建计策未指定演出时，根据名称和效果选用相应的回退画面与音效。

原作音乐的权利归其权利人所有，不属于本项目生成素材的许可范围；对外分发或部署这些音频前需自行确认使用权限。

### 使用 Docker Compose

需要 Docker 和 Docker Compose。构建前先按「获取代码与素材」下载并解压与代码版本对应的素材包；素材会打包进镜像，更新素材或代码后重新运行 `make up` 即可重新构建。构建时只检查两个关键素材，完整性请使用上面的 SHA-256 校验命令确认。

Dockerfile 从 `reg.deeproute.ai` 拉取 Node 和 Python 基础镜像。本次验证的镜像为 `linux/amd64`；在 ARM 主机上运行需要支持 amd64 模拟。

```bash
make up       # 构建镜像并在后台启动
make ps       # 查看服务状态
make logs     # 查看服务日志，按 Ctrl+C 退出
make down     # 停止并移除容器
```

客户端提前断开连接时，日志会保留一条简短提示；其他服务端异常仍会输出完整堆栈。

打开 http://localhost:8677/hd2d-mvp/ 。也可单独执行 `make build` 构建镜像。默认只监听本机的 8677 端口；可以通过环境变量修改监听地址和宿主机端口，例如：

```bash
GAME_BIND_ADDRESS=0.0.0.0 GAME_PORT=8080 make up
```

游戏记录保存在浏览器本地，容器不保存存档；更换浏览器或访问地址后不会自动共享记录。
普通记录读取时会检查武将、所属势力及城市武将引用；结构损坏时尝试恢复上一份有效备份，损坏记录不会替换备份，也不能作为新记录写入。有效的旧记录、动态武将和中断守城记录继续保留。
当前版本的普通记录和快捷存档使用 IndexedDB 协调不同页面的写入，支持 Web Locks 时也会使用该锁；IndexedDB 不可用时会提示无法安全写入，避免覆盖其他页面的记录。检测到不同版本的记录时会要求重新确认；已存在的、来自更新版本的普通记录不会被旧版本覆盖。已打开的旧版页面可能不参与协调，更新后请关闭旧版页面。

### 游戏版本管理

管理员可在标题画面选择「☰ 系统 → 版本管理」，或打开 `/hd2d-mvp/admin.html`。管理页面可以基于原版、内置版本或已发布版本编辑人物属性、出生与登场信息、人物关系、新武器、新防具和新技能，再发布给使用同一服务器的玩家。原有美术素材包提供 237 套人物立绘及表情和 24 个武器图标。
手机窄屏下「版本管理与发布」默认折叠，展开后可载入、导入、导出及发布版本；编辑分类导航保持在页面顶部，操作状态在折叠时仍可查看。

标题提供「原版」和「群英新篇·君主列传」，以及管理员已发布的版本；新会话默认进入君主列传。君主列传包含此前「群英新篇」和「巾帼群英」的内容，例如可通过城市搜索登场的孙尚香、甄宓、貂蝉、蔡琰、王异、陈宫和高顺。编辑器可将这些人物以及陈到、辛宪英作为模板加入其他版本，并分别选择或上传立绘、平静／喜悦／愤怒／悲伤表情及动作。立绘和表情上传支持 PNG、JPEG、WebP；动作上传使用透明 PNG 或 WebP 正方形 4×4 网格，浏览器会规范为 512 × 512 PNG。帧的顺序与素材示例见 [角色素材说明](hd2d-mvp/assets/characters/README.md)。原有「上传人物图片」仍按旧版方式将不超过 64 KB 的图片放入版本文件，未单独配置表情时共用。

人物图片或素材索引遇到临时加载失败时会有限重试；可见图片长时间未加载时也会重试。仍不可用时优先回退到同一人物的普通头像，所有来源均失败时显示内置占位图。离屏懒加载图片不会因尚未进入视口而触发超时重试。

标题只列出原版、君主列传和管理员发布的版本。旧「巾帼群英」「群英新篇」「新阵容」「十方诸侯」和君主列传旧标准地图不再提供记录入口；浏览器中已有的数据不会自动删除，也不会迁移到新版。若页面上次停留在这些旧版本，会转到君主列传扩展地图。原版和新版记录仍各自保存；玩家可在版本菜单选择原版或已发布版本，选择在当前浏览器标签页会话中保留，刷新页面不会切回默认版本。

君主列传及启用新版玩法的自定义版本，新开局的战场计略阈值按完整数值计算并限制在 5～95，避免智力和等级优势过大时因 8 位溢出降至最低；实际成功率仍使用原有随机表和君主被动。原版及本次更新前的存档、中断战斗继续使用原有判定，不会自动改变规则。

君主列传的新征程默认使用扩展地图，标题和开局页面不再显示地图切换。原版维持 30 城；扩展地图增加襄阳、江州、宛城和夷洲，共 34 城，并增加虎牢关、函谷关、武关、剑阁和望垣峡五处关隘。望垣峡位于西平关与成都之间的示意道路上，夷洲通过海路与建安相连；两个新据点开局无主，电脑和玩家都可争夺。新城和关隘的资源、路线及归属是游戏设定，战场复用相近地区的地形和布阵。

君主列传扩展地图新开局调整八名女将的初始能力（体力／武力／智力／人德）：孙尚香 88／89／76／80，甄宓 78／62／91／86，貂蝉 81／70／89／82，蔡琰 78／42／94／85，王异 86／85／86／90，辛宪英 76／40／94／90，黄夫人 78／42／93／90，祝融夫人 88／88／72／78。武将型和谋士型仍各有侧重；登场时间、地点、技能和装备不变。旧存档和中断战斗保留记录中的能力与体力上限，原版及已发布的自定义版本不受影响。

扩展地图中，新野与衡阳之间须经过襄阳，洛阳与荆州之间须经过宛城；进攻、调兵、运输和电脑决策共用这些相邻道路。调整前已经中断的战斗仍可恢复，并可撤回原出阵地；原版地图的道路不变。襄阳、宛城、函谷关和武关的位置及附近遮挡已调整，城市、关隘及其连接道路更容易辨认；这些位置调整不改变相邻道路或战斗规则。

「望垣硖」见于[《三国志》卷六·董卓传](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B706)；游戏中的位置和关隘建制是示意，并非精确复原。《三国志》卷四十七记载东吴于 230 年派人到[夷洲](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B747)，其确切地理对应存在争议。将夷洲放在东南海岛、设为 189 年可占领城市并连接建安，均为游戏安排，不代表当时的行政建制或航线。

关隘是可驻军、运输补给和争夺的道路据点：移动至无主关隘即可占领，敌方驻军须通过战争击败；失去最后一名驻守武将时关隘成为无主。关隘不计入城市数量、命令书、税收、城市灾害、暴乱和山贼海贼袭城，也不能开发、防灾或征兵。可从相邻己方城市运输金米，军队出阵也可携带军资；将领和君主可驻守或通过关隘，向关隘移动或出阵时须在最后一座城市至少留守一名武将。旧方案中君主在关隘的每月被动仍可作用于军资和驻守武将，土地、统治及预备兵类效果不生效。关隘战斗使用现有的玩家战场或电脑自动结算，攻占关隘不会同时占领相邻城市；仍可通过其他实际存在的道路绕行。

扩展地图的襄阳和宛城加入旱灾范围，襄阳、江州和夷洲加入洪水范围；夷洲也可能遭海贼袭扰。命令书在 30 城以上不再增长。电脑会尝试占领空关、从连通的己方城市调兵补给并从关隘继续进攻；关隘驻军补兵先使用关内已有后备兵，再使用连通城市的后备兵，不足时使用城市资金征兵，无法连通时不会凭关隘自身的金凭空增兵。势力失去最后一座城市时，即使仍驻守关隘也会灭亡；统一胜利按 34 座城市判断，不要求所有关隘归属。

君主列传原有的 37 据点扩展地图记录读取时会补入无主的望垣峡和夷洲，不重置既有城市、人物或中断战场；因此统一目标也扩展为 34 城。不同版本的普通、快捷、自动续玩及战场中断记录仍分别保存。管理员可在版本编辑器为扩展地图开启「新增边地据点」；未启用该选项的已发布版本保持原来的 33 城和四处关隘，标准地图和原版不受影响。包含这一设置的自定义版本需要更新后的客户端和服务器。编辑器中的人物登场地点和装备商店目前仍限原有 30 城。

电脑之间的自动战斗仍是抽象结算：能从参战人数、关系、兵种、攻守和地图粗略判断的君主效果按最多 2 点战力估算，不逐次模拟白兵。刘备的专属效果按实际人物关系判断，独立于招募等通用关系效果的开关。君主被俘、阵亡或继位后使用现任君主的效果；君主在战场被击败后不再提供该场增益。原版及缺少相应设置的旧记录继续使用原有被动。

君主列传的新开局中，十位原有君主各自持有一件专属武器，图标沿用现有素材。其攻击力为 20–22，不低于内置普通武器；为控制叠加幅度，不再额外添加武器专属属性。专属武器绑定对应人物，不在城市或战场商店出售，也不会作为战利品转移。人物继位、被俘、下野或不再执掌势力时仍持有；主动更换武器后专属武器消失，不能再次获得。更换前会提示；自动战利品不会覆盖专属武器。记录编辑器可撤销尚未写回的更换，但不能把专属武器分配给其他人物或在写回后重新获取。

这些武器不含两格远射，使用原有近战和单挑规则；编号不变，内置君主列传旧记录中仍持有它们的人物会使用更新后的名称与数值，已经更换的装备不会恢复。原版装备不变；原有可作为单挑战利品的「倚天剑」和新增绑定装备「倚天剑·孟德」是不同装备，前者仍按原规则获得。版本编辑器可调整新草稿中专属武器的属性与图标，但不能将其设为商店商品或分配给其他人物。选择额外君主候选时，原君主仍随身持有自己的武器；已发布的自定义版本保留自己的装备配置。

新版玩法在已有战场技能上增加受限条件：刘表「荆襄固阵」的施术者在城中时额外损兵 25；田豫「北疆守御」的目标距己方总大将两格内时额外限制移动 1 日；牵招「牵招镇边」的目标兵力至少 400 时额外损粮 30。命中、机动力和次数限制照旧，玩家和电脑均适用。编辑器可选择这些固定条件效果，只有启用新版玩法的新开局生效。

新版关系补充刘备、关羽、张飞的结义，刘备与诸葛亮的君臣，曹操与夏侯惇的亲属，孙策与周瑜的朋友关系；这些关系只在启用新版玩法的记录生效。编辑器列出既有及新版关系，新规则拒绝同一种关系的反向重复；未启用新版玩法的旧版本仍按原有格式读取。

新版电脑选择进攻目标时兼顾守将、兵力、军粮与关隘；战场直行受阻时会在可达范围内绕行，持续跟随可行路线以避免重复往返，并优先攻击相邻且已明显虚弱的敌方总大将。关隘守方获得少量战斗优势，自动战斗也少量计入装备与关隘守备。电脑同盟报价超过 255 时按全额报价与支付；原版及缺少新版玩法标记的旧记录保留原有规则。

190 年起，新版玩法中的地方建言每个符合条件的势力每月有 3% 的检查概率，全图当月最多一次、同一势力至少间隔 24 个月；当月受灾、发生战争或遭袭的势力不会触发。玩家可选择花费 80 金使防灾＋5、土地＋3，或换取 100 米，也可暂不办理；电脑会根据粮食情况选择。资源和建设值遵守原有上限，选项显示上限内的实际增量；没有收益的选项不可选，重复选择不会重复扣费或领取。

君主列传修正电脑补兵：先使用后备兵，再按每 20 金征集 100 人；资源不足时仅补充可负担的人数，出阵整备也不再多征收不需要的兵。原版、十方诸侯及旧的已发布版本继续保留原版字节判断和扣费行为；管理员可在「君主候选」中为草稿启用修正规则，并发布新版本。此设置不改变玩家征兵规则。

君主列传的新开局中，公孙瓒、袁术、刘表的开局城市分别获得金与米各 900、450、1200，后备兵保留各城原值。这些数值改善单城势力的早期资源，玩家与电脑使用相同开局；编辑器的「君主候选」可调整各新势力的开局金、米和后备兵。已有存档的城市资源不会重置，君主列传的旧存档恢复后采用更新后的电脑补兵规则。包含开局资源、补兵规则或技能演出设置的已发布版本需要更新后的客户端和服务器。

君主列传的新开局启用增强灾害：洪水和旱灾仍在原有月份发生，标准地图的城市范围不变，扩展地图额外城市的灾害范围见上文。受灾时城市金、米各至少损失 50，土地和产业各至少损失 5，现有数量不足时最多扣除现有数量。防灾值越高，额外损失越少；洪水对米和产业、旱灾对土地和驻军的影响更大。同一城市在相邻月份连续受灾时，第二次的额外损失减半，但每次的资源和建设损失保底仍然生效。事件会显示实际损失。版本编辑器的「增强灾害影响」可为新开局启用或关闭此规则，开局时的设置随存档保存；已启用增强灾害的存档使用更新后的损失规则，未启用的旧存档和原版继续按原灾害规则结算。旧存档首次读取前未保存的受灾时间无法追溯。包含此设置的已发布版本需要更新后的客户端和服务器。

君主列传的新开局还启用山贼、海贼守城和电脑补兵优先级优化，可在版本编辑器的「君主候选」中分别设置；已有存档保留开局时的设置。190 年起，守军至少 100 人、太守体力至少 20 且粮草足够约 20 日的城市可能遭袭；每个符合条件的玩家势力每月抽取一次，概率为 5%，电脑为 1%。内陆城市当月发生暴乱时，同一次抽签可能引来山贼，玩家遇到的敌兵约为驻军的 30%；电脑遇到的暴乱袭扰更弱。其他暴乱冷却初期不叠加随机袭扰，近海暴乱不会引来山贼。全图每月最多一场，同一势力和城市至少间隔 18 个月；势力的城市受灾当月、经历普通战争的当月及下月不会遭遇袭扰，袭扰当月电脑不会再攻打该势力。辽东、青州、徐州、扬州、建安、交州和夷洲为近海海贼，其余城市为山贼。玩家遇到普通袭扰时敌兵约为驻军的 40%，最多 2000 人；电脑遭遇较弱并自动结算，贼军不会占领电脑城市。守城败北时城市金、米、土地和产业损失 5%；受到致命伤或被擒的普通守将战后下野，玩家君主阵亡则游戏失败，启用「武将不战死」时君主仍受保护。若玩家城市无人留守，城市变为无主。守城支持战场中断和手机自动续玩，临时敌军不会加入人物名册。

启用「优化电脑补兵优先级」并同时启用「修正电脑补兵」后，电脑优先考虑实际可补兵数，同时更重视前线和君主城的防守。已启用此优化的存档使用更新后的排序；原版及未启用优化的旧记录继续使用原有选择顺序。开启增强灾害、守城或新补兵设置的已发布版本需要更新后的客户端和服务器。

新增人物的游戏设定：蔡琰（蔡文姬）207 年在长安搜索、王异 213 年在凉州搜索、陈宫 192 年在兖州搜索、高顺 192 年在洛阳搜索。出生年月与出生地不确定时留空；登场城市、年份和属性均为玩法设定，不表示历史上曾于该城出仕。蔡琰见[《三国演义》第七十一回](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9/%E7%AC%AC071%E5%9B%9E)；王异是[《三国演义》第六十四回](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9/%E7%AC%AC064%E5%9B%9E)的赵昂妻王氏，姓名见[《三国志》卷二十五裴注所引《列女传》](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B725)；陈宫见[《三国志》卷七](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B707)，高顺见[《三国演义》第十九回](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9/%E7%AC%AC019%E5%9B%9E)。蔡琰和王异的年老判定起始年 240 只是游戏阈值，并非已知卒年。

为保证陈宫和高顺有足够的登场机会，他们从 192 年起优先进入所在城市的搜索候选，玩家和电脑均适用；之前及他们登场后其他人的搜索顺序不变。版本编辑器的「登场后优先搜索」可为城市搜索登场的人物设置相同规则，仍需满足城市空位等条件。

「群英新篇」为诸葛亮、周瑜、陈宫、蔡琰、王异、郭嘉和司马懿配置各自的战场计略，采用现有的损兵、伤体力、限制移动或损粮效果，每名武将每场战斗最多尝试两次，失败也消耗次数，战场中断后次数仍保留。关羽、张飞、赵云、吕布、孙尚香、王异、高顺、张辽、许褚和黄忠分别拥有专属单挑技，每场单挑可尝试一次；吕布的「方天破阵」命中阈值减 10、伤害为普通攻击的 120%，张辽的「逍遥突击」命中阈值加 5、伤害为 115%，许褚的「虎痴猛击」命中阈值减 10、伤害为 125%，黄忠的「老将劲击」命中阈值加 5、伤害为 110%。招式不附带远射或额外行动。玩家和电脑均可在实际战场中使用；电脑之间直接结算的战争仍使用原版抽象规则，不逐个施展这些技能。原版及「巾帼群英」不自动获得这些招式。编辑器添加角色模板时会附带该角色的预设计略或单挑技，并复用已存在的同名计略，不覆盖已有调整；也可为武将选择固定单挑技，或为自定义计略设置每场 1–3 次的上限，未设置时沿用旧版不限次数的行为。

自定义计略的限制移动效果不会缩短目标已有的限制；电脑会结合命中率与可产生的效果选择目标。

内置角色的姓名沿用常见称谓：孙夫人本名及出生年月不详，「孙尚香」是后世通称；「甄宓」也是后世称谓，甄后是中山无极人，出生年按《三国志》裴注所引记载折算为 183 年；貂蝉则是《三国演义》中的文学人物。未知出生年月和出生地留空，籍贯不等同于出生地。见[孙夫人姓名考证](https://www.cne3online.com/culture/view/14041440/140530116025228.shtml)、[《三国志》卷五](https://zh.wikisource.org/zh/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B705)、[甄氏姓名考证](https://cne3online.com/culture/view/13280256/132885546021186.shtml)、[中国文化研究院：《三国演义》的连环计](https://chiculture.org.hk/sc/china-five-thousand-years/397)。

合并版的落日弓重量为 6、凤羽宝衣重量为 5；电脑在有扩展装备的城市会比较可负担装备的攻防、重量和购买条件，并可为合适的武将购入弓或扇。原版和旧「巾帼群英」维持原有购买规则及装备数值：旧版落日弓攻击 15，凤羽宝衣防御 12、重量 4、价格 420、人德要求 80。旧「群英新篇」记录不再提供入口；已发布的自定义版本保留各自保存的装备数值与技能配置。编辑器添加模板时，若草稿已有同名、同类型和同图标的装备，也会沿用其已有数据。

包含新武器类别、防具或搜索优先设置的版本需要更新后的客户端与服务器；已发布的旧版本仍可读取。升级后如果玩家仍开着旧页面，请刷新后再选择新版本。

上传独立素材前先在管理页面输入管理员令牌。输入图片最多 8 MiB、1600 万像素，单个素材压缩后最多 1 MiB，单个版本最多引用 128 个不同素材、合计 16 MiB；版本 JSON 本身仍限 1 MiB。动作图须包含透明背景和可见图像。素材按内容哈希去重，存放在版本目录的 `assets/` 中，由玩家按需读取；上传后放弃草稿或发布失败时，未引用素材不会自动删除。游戏会在加载动作网格时统一各帧的角色比例、适度减少脚底留白，并为白兵和单挑移动使用行军帧；过宽的单行动作条会重新排列为多行，避免在纹理宽度有限的设备上缩小整张动作图。

原版数据没有内置人物关系记录；编辑器列出当前版本的关系，支持筛选及添加亲属、朋友、父子、兄弟、结义、君臣等关系，也可输入不超过 16 字的关系名称。关系在双方资料中使用相同名称。君主列传的新开局启用关系效果：亲友和敌对关系可影响寻访、内政诱纳与战场笼络，按招募方和原势力君主与目标的关系综合判断，多条关系不叠加。一般诱纳的实际成功率最多变化 5 个百分点，特定人才寻访按原版的 16 档概率变化一档；原有无法招募条件不变。入仕时与新君主的关系可使忠诚增加或减少 5，非指定继位时可使忠诚变化增加或减少 2；已有 90 以上的入仕忠诚不会因此降低。亲近与敌对关系同时存在时抵消，无法识别的自定义关系只展示。玩家和电脑使用同样的关系规则。

君主列传的新开局还会在电脑势力之间的自动战争中计入专属技能：每名有兵、体力未耗尽的参战武将最多计入一个机动力上限允许施展的专属计略和一次单挑技，损粮计略只按对方持有的粮草估算。双方的技能战力加成各不超过自身基础战力的 10%，且最多 12 点；战报会显示实际加成。自动战争仍为抽象结算，不逐次模拟施技、额外扣兵扣粮或追加随机数。版本编辑器可分别启用人物关系效果和电脑战斗技能；设置随新开局保存，原版、缺少设置的已发布版本以及现有存档继续使用原规则。包含新设置的已发布版本需要更新后的客户端和服务器。新技能可组合固定的损兵、体力伤害、限制移动和粮草损失效果，不执行自定义代码。

君主列传的新开局还修正电脑诱纳概率：负值限制为零，避免原版的无符号数回绕导致必然成功。版本编辑器「君主候选」可配置该规则；设置随新开局保存，原版、未启用的已发布版本和旧存档保持原有计算。

君主列传的新开局为 66 名名将配置特色兵队，其余武将保留原有步、弓、骑配比。编辑器「人物与登场」可开关规则、选择兵种、设置个人上限或恢复默认；设置随新开局保存，原版、旧存档和未启用的已发布版本继续使用原规则。特色兵队与「平／山／水军」地形适性独立，换装备或补兵不改变配置。

每队最多代表 100 兵。特色队的实际数量同时受目标兵种上限、武将个人上限、等级上限和可用兵队限制：1–2 级最多一队，3–5 级最多两队，6–8 级最多三队；总队数较少时还受到每四队至多一支特色队的约束。野战至少有六队且原配比没有对应兵类时转换一队；君主列传新开局启用低级骑兵平衡，1–2 级武将不会把步兵或弓兵强行转换为骑兵，原编成已有骑兵时仍可部署特色骑兵。该设置可在版本编辑器开关，随新开局保存，旧存档和未启用的版本维持原有转换规则。守城不强行转换，守城步兵仍按原版转为弓兵。级别不足时使用表中的低级兵种，升级后的转换从下一场白兵开始。目标兵种的上限在低级阶段也生效；因此皇家骑兵和骑射兵的后备兵队最多一队。

出生年份和出生地用于人物资料，登场年份、地点和方式决定人物何时进入游戏。原有君主的开局位置不可修改；如果调整登场导致某城开局没有武将，该城会成为无主城。编辑器还可将某个势力的开局武将设为额外君主候选；玩家开局时可以选择这些候选，其所在势力由选中人物统领，原君主留在该势力。此功能不增加势力数量，旧版本与原版保留原有七位君主。

服务器默认允许读取已发布版本，**未配置管理员令牌时不允许发布**。令牌需为 32–256 位不含空格的可打印 ASCII 字符，请使用密码管理器生成的高强度随机值。首次启动或轮换令牌时，在当前终端输入令牌（输入不会回显）：

```bash
read -r -s GAME_ADMIN_TOKEN
export GAME_ADMIN_TOKEN
make up
```

Compose 会将令牌的 SHA-256 校验值保存在独立的 `game_admin_token` 持久卷中，文件仅允许所有者访问；不会把令牌原文写入该卷、浏览器或版本文件。随后容器重启或重建时，即使没有环境变量，也会继续使用已保存的令牌。该配置依赖同一 Compose 项目中的持久卷；迁移宿主机或更换项目时需迁移该卷或重新配置令牌。已有部署升级到此功能后，首次启动仍需提供原令牌一次，才能写入新的持久卷。

发布时在管理页面输入相同令牌；发布成功后输入框会清空。需要轮换令牌时，以新令牌重新执行上述命令；启动后旧令牌失效。使用同一可信持久令牌文件的运行中实例会在每次发布认证时读取最新校验值，轮换后的认证请求会使用新令牌；只使用进程内令牌的实例不会自动同步。启动时非空的 `GAME_ADMIN_TOKEN` 总是覆盖已保存的校验值，因此轮换后应协调所有实例的配置，避免其他实例重启时再次提供旧令牌。令牌文件和所在目录须由服务运行用户或 root 所有；文件不得允许其他用户访问，目录不得允许其他用户或用户组写入。无效的环境变量、不可写或损坏的令牌文件会禁用发布并记录错误，不会用错误令牌覆盖已保存的配置。首次启动时传入的环境变量仍可被具有 Docker 管理权限的人查看；若不再需要它，可在终端执行 `unset GAME_ADMIN_TOKEN`，然后重新执行 `make up`。

静态服务拒绝访问隐藏文件及指向 `.env` 配置的链接，`.env*` 也被排除在 Git 和 Docker 构建上下文之外。仍建议不要把真实令牌放在项目目录内。默认端口仅绑定本机；通过网络管理时，应使用 HTTPS 反向代理保护令牌。

玩家在标题画面选择「☰ 系统 → 游戏版本」，新会话默认使用君主列传；即使版本服务不可用，也可选择原版和内置版本。每次修改后发布都会创建不可覆盖的新版本编号，原版及各版本的普通、快捷、自动和中断战斗记录分别保存。管理页面可以导入、导出版本 JSON；含上传素材的版本会导出为包含素材的 JSON 包，在其他服务器导入时需先填写管理员令牌。未经修改的导入文件可用原编号恢复已发布版本。版本绑定当前基础数据，基础数据发生变化后需要先确认兼容性，不能直接当作新版加载。独立 Electron 离线包可选择原版及内置版本；服务器版本管理需要通过游戏服务器访问。

无法读取的单个版本会从列表中跳过，管理页面和游戏版本选择界面会提示数量，其他正常版本仍可使用。服务器日志会记录被跳过的版本编号，管理员可检查版本文件或从备份恢复；服务器不会自动删除或覆盖这些文件。整个版本目录无法访问时，列表仍会报告服务错误。

Compose 将已发布版本及其上传素材保存在 `game_versions` 卷，管理员令牌校验值保存在 `game_admin_token` 卷；`make down` 不会删除它们。删除对应卷会分别删除已发布版本及素材或令牌配置。迁移或备份版本时应保留整个版本目录及其 `assets/` 子目录。直接运行开发服务器时，版本默认保存在 `~/.local/share/threekindoms/versions`，可用 `GAME_VERSION_DIR` 指定其他可写目录；若也需要持久化令牌，设置 `GAME_ADMIN_TOKEN_FILE` 为静态服务目录之外的绝对文件路径。未设置该路径时，直接运行的服务器仅在当前进程内使用令牌。

node --test hd2d-mvp/tests/artcoverage.test.mjs                  # 单个测试文件

## 打包桌面版

需要 `cwebp`（macOS 上用 `brew install webp` 安装）。

```bash
npm --prefix hd2d-mvp/desktop run dist:mac    # macOS dmg（arm64 与 x64）
npm --prefix hd2d-mvp/desktop run dist:win    # Windows x64 zip
npm --prefix hd2d-mvp/desktop run dist:dir    # 只出 macOS 的 .app 目录，最快
npm --prefix hd2d-mvp/desktop start           # 直接用 Electron 运行游戏（需要先执行一次 build-app）
```

这几个命令都会先运行 `build-app.mjs`，把游戏快照到 `hd2d-mvp/desktop/app/`，产物放在 `hd2d-mvp/desktop/release/`。
