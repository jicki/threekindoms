# Three Kingdoms HD-2D（三国 HD-2D）

一款回合制三国战略游戏的 HD-2D 重制：像素角色立在 3D 地形上，加上实时光影、景深与后期。玩法规则和数值参照 1992 年 FC 游戏《三國志II 覇王の大陸》。游戏用浏览器运行（three.js），也能打包成 Electron 桌面版。

> 本项目是非官方、非商业的同人重制，与 Bandai Namco 无关。仓库不包含原版 ROM，但包含原版和 PS 复刻版音乐及部分音效。立绘等美术由 AI 生成，经人工筛选与修改。

## 项目结构

```
hd2d-mvp/
  index.html          游戏入口
  save-editor.html    存档（记录）编辑器
  vignettes.html      命令演出预览页
  src/
    core/             规则层，不依赖渲染：
                        game.js 战略层与全部命令、ai.js 战略 AI、warcore.js 开战与战后写回、
                        field.js 战争地图、tactical.js 白兵、skirmish.js 白兵与单挑结算、
                        saveedit.js 记录编辑、ahuinan.js 阿会喃漏洞模式
    war/              战争地图 3D 视图（board、units、overlay、camera、pick、interact、play、probe）
    *.js              three.js 场景（strategy*.js 战略地图、warview.js 战场、tacticalview.js 白兵、
                      duelview.js 单挑等）与流程、界面（app.js、ui.js、ui.css）
  data/
    game-data.json    武将、城市、地图、事件等全部规则数据
    thanks.txt        片尾鸣谢名单
  assets/             美术、3D 模型与音效（素材包，见下文）；manifest.json 列出可选资源
  tests/              测试（*.test.mjs），公共辅助函数在 game.mjs
  tools/              开发服务器、无头浏览器、截图与检查、模拟，以及美术切图与烘焙脚本
  desktop/            Electron 打包脚本
```

## 获取代码与素材

仓库包含代码、数据、已收录的音乐与音效，以及内置角色的美术素材。原有美术、3D 模型、其他音效和图标放在 [Releases](https://github.com/tianlin/threekindoms/releases) 的素材包 `threekindoms-assets-<版本>.zip` 里。

```bash
git clone https://github.com/tianlin/threekindoms.git
cd threekindoms
# 从 Releases 下载与代码对应的素材包（跟进 main 就用最新的），解压到仓库根目录：
unzip -o ~/Downloads/threekindoms-assets-0.3.6.zip
shasum -a 256 -c ASSETS.sha256 | grep -v ': OK$'    # 没有输出就说明素材齐全
```

素材包中的文件已经写进 `.gitignore`，解压后不会出现在 `git status` 里。根目录的 `ASSETS.sha256` 列出了素材包中文件的哈希：
- 解压后如果 git 显示 `ASSETS.sha256` 被修改，说明素材包和代码版本不一致，请换用对应版本的素材包。
- 缺少素材时，开发服务器、`tests/lfs-pointer.test.mjs` 和桌面版打包都会提示你先解压素材包。

## 运行

需要 Node.js 22 以上和 Python 3。

```bash
npm --prefix hd2d-mvp/desktop install     # 首次：安装 three.js、字体和 Electron
python3 hd2d-mvp/tools/serve.py 8677      # 启动开发服务器
```

然后用浏览器打开 http://localhost:8677/hd2d-mvp/ 。在网址后面加 `?mute` 可以静音。

### 战场操作

可点击武将所在格或姓名选择武将；画面拥挤或人物被遮挡时，使用战场右下角的「选将」从我军名单选择。布阵时也可以用此名单或手机上的 ‹、› 切换武将；电脑键盘使用 `[`、`]` 切换。正在选择攻击或计略时，先完成或取消该指令再使用名单切换。点击姓名会优先选中对应武将，若姓名挡住目的地，可按住 `T` 或点「地形」后选择地格。

### 战场生死

开局时或游戏中的「☰ 系统 → 战场生死」可选择原版规则或「不战死」，选择随本局存档保存。开启后，白兵、单挑和计略中体力归零的武将与君主会退出战场并被对方俘获；电脑之间的战争也将伤亡改为被俘。君主恢复体力至 30，但不超过其体力上限。

战败君主无路可退时优先由胜方俘获；俘获方没有可用位置时君主下野。君主被俘或下野后，原势力有部下时选择继承者，否则势力灭亡；总大将被俘仍会结束战斗。开启不战死不会阻止病逝，病逝由「武将不老」单独控制。单挑宝物仍须实际斩杀才能获得，被俘不会触发斩杀奖励。

### 背景音乐

游戏会自动检查本地可选音频。在标题页或游戏中的「☰ 系统 → 曲目」可以切换已提供的音乐版本，选择保存在当前浏览器中；浏览器可能要求先点击页面才能播放。没有可用音频时，部分场景使用合成音乐。已有的 `remix/` 素材仍显示为 Remix，不会误认为 PS 复刻版。

原版和 PS 复刻版音频放在 `hd2d-mvp/assets/audio/original/` 和 `hd2d-mvp/assets/audio/ps/`，文件名与 `assets/manifest.json` 中的对应场景一致。已收录的 16 首背景音乐、事件短曲、单挑音效，以及爆炎和碰撞音效随 Git 仓库提供，无需另行下载；其他本地音频仍被忽略。音频保留现有的 M4A 和 MP3 格式，避免对有损素材重复转码。构建 Docker 镜像或桌面版时会打包这些音频；加入或更换音频后需要重新构建。

目前接入的场景及音源对应关系如下。FC 音频来自 [原版 NSF 曲目表](https://www.zophar.net/music/nintendo-nes-nsf/sangokushi-2-haou-no-tairiku)，PS 曲目编号来自 [Namco Anthology 1 音源](https://downloads.khinsider.com/game-soundtracks/album/namco-anthology-1-ps1-gamerip-1998)，结合[场景曲目资料](https://w.atwiki.jp/gamemusicbest100/pages/5645.html)及旋律特征比对；结局使用 [PSF 音源](https://ftpmirror2.infania.net/sites/modland/incoming/warehouse/PSF/HaounoTairiku_psf/HaounoTairiku_ezp104_PSF/)中标注为 Epilogue 的曲目。PS 版战后和失败暂未找到可可靠对应的文件，选择 PS 版时会回退到该场景的其他可用版本。

### 使用 Docker Compose

需要 Docker 和 Docker Compose。构建前先按「获取代码与素材」下载并解压与代码版本对应的素材包；素材会打包进镜像，更新素材或代码后重新运行 `make up` 即可重新构建。构建时只检查两个关键素材，完整性请使用上面的 SHA-256 校验命令确认。

Dockerfile 从 `reg.deeproute.ai` 拉取 Node 和 Python 基础镜像。本次验证的镜像为 `linux/amd64`；在 ARM 主机上运行需要支持 amd64 模拟。

```bash
make up       # 构建镜像并在后台启动
make ps       # 查看服务状态
make logs     # 查看服务日志，按 Ctrl+C 退出
make down     # 停止并移除容器
```

客户端提前断开连接时，日志会保留一条简短提示；其他服务端异常仍会输出完整堆栈。

打开 http://localhost:8677/hd2d-mvp/ 。也可单独执行 `make build` 构建镜像。默认只监听本机的 8677 端口；可以通过环境变量修改监听地址和宿主机端口，例如：

```bash
GAME_BIND_ADDRESS=0.0.0.0 GAME_PORT=8080 make up
```

游戏记录保存在浏览器本地，容器不保存存档；更换浏览器或访问地址后不会自动共享记录。
当前版本的普通记录和快捷存档使用 IndexedDB 协调不同页面的写入，支持 Web Locks 时也会使用该锁；IndexedDB 不可用时会提示无法安全写入，避免覆盖其他页面的记录。检测到不同版本的记录时会要求重新确认；已存在的、来自更新版本的普通记录不会被旧版本覆盖。已打开的旧版页面可能不参与协调，更新后请关闭旧版页面。

### 游戏版本管理

管理员可在标题画面选择「☰ 系统 → 版本管理」，或打开 `/hd2d-mvp/admin.html`。管理页面可以基于原版、内置版本或已发布版本编辑人物属性、出生与登场信息、人物关系、新武器、新防具和新技能，再发布给使用同一服务器的玩家。原有美术素材包提供 237 套人物立绘及表情和 24 个武器图标。

标题的内置版本「群英新篇」合并了「巾帼群英」的内容，包含孙尚香、甄宓、貂蝉、蔡琰、王异、陈宫和高顺，均可通过城市搜索登场；原版仍为默认。编辑器可将七人作为模板加入其他版本，并分别选择或上传立绘、平静／喜悦／愤怒／悲伤表情及动作。立绘和表情上传支持 PNG、JPEG、WebP；动作上传使用透明 PNG 或 WebP 正方形 4×4 网格，浏览器会规范为 512 × 512 PNG。帧的顺序与素材示例见 [角色素材说明](hd2d-mvp/assets/characters/README.md)。原有「上传人物图片」仍按旧版方式将不超过 64 KB 的图片放入版本文件，未单独配置表情时共用。

「群英新篇」使用独立存档，不改变原版和旧「巾帼群英」的现有记录或动态武将编号。浏览器中存在旧记录、中断战斗或备份时，标题的「游戏版本」仍提供「巾帼群英（旧存档兼容）」供继续旧记录；该入口沿用旧规则，不会自动增加新人物或技能。旧版标题的「进入群英新篇」可切换到合并版开始新游戏，两个版本的记录不会自动合并或覆盖。

新增人物的游戏设定：蔡琰（蔡文姬）207 年在长安搜索、王异 213 年在凉州搜索、陈宫 192 年在兖州搜索、高顺 192 年在洛阳搜索。出生年月与出生地不确定时留空；登场城市、年份和属性均为玩法设定，不表示历史上曾于该城出仕。蔡琰见[《三国演义》第七十一回](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9/%E7%AC%AC071%E5%9B%9E)；王异是[《三国演义》第六十四回](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9/%E7%AC%AC064%E5%9B%9E)的赵昂妻王氏，姓名见[《三国志》卷二十五裴注所引《列女传》](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B725)；陈宫见[《三国志》卷七](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B707)，高顺见[《三国演义》第十九回](https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%9C%8B%E6%BC%94%E7%BE%A9/%E7%AC%AC019%E5%9B%9E)。蔡琰和王异的年老判定起始年 240 只是游戏阈值，并非已知卒年。

为保证陈宫和高顺有足够的登场机会，他们从 192 年起优先进入所在城市的搜索候选，玩家和电脑均适用；之前及他们登场后其他人的搜索顺序不变。版本编辑器的「登场后优先搜索」可为城市搜索登场的人物设置相同规则，仍需满足城市空位等条件。

「群英新篇」为诸葛亮、周瑜、陈宫、蔡琰和王异配置各自的战场计略，采用现有的损兵、伤体力、限制移动或损粮效果，每名武将每场战斗最多尝试两次，失败也消耗次数，战场中断后次数仍保留。关羽、张飞、赵云、吕布、孙尚香、王异和高顺分别拥有专属单挑技，每场单挑可尝试一次；吕布的「方天破阵」命中阈值减 10、伤害为普通攻击的 120%。招式不附带远射或额外行动。玩家和电脑均可在实际战场中使用；电脑之间直接结算的战争仍使用原版抽象规则，不逐个施展这些技能。原版及「巾帼群英」不自动获得这些招式。编辑器添加角色模板时会附带该角色的预设计略或单挑技，并复用已存在的同名计略，不覆盖已有调整；也可为武将选择固定单挑技，或为自定义计略设置每场 1–3 次的上限，未设置时沿用旧版不限次数的行为。

自定义计略的限制移动效果不会缩短目标已有的限制；电脑会结合命中率与可产生的效果选择目标。

内置角色的姓名沿用常见称谓：孙夫人本名及出生年月不详，「孙尚香」是后世通称；「甄宓」也是后世称谓，甄后是中山无极人，出生年按《三国志》裴注所引记载折算为 183 年；貂蝉则是《三国演义》中的文学人物。未知出生年月和出生地留空，籍贯不等同于出生地。见[孙夫人姓名考证](https://www.cne3online.com/culture/view/14041440/140530116025228.shtml)、[《三国志》卷五](https://zh.wikisource.org/zh/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B705)、[甄氏姓名考证](https://cne3online.com/culture/view/13280256/132885546021186.shtml)、[中国文化研究院：《三国演义》的连环计](https://chiculture.org.hk/sc/china-five-thousand-years/397)。

游戏内可搜索登场的年份和城市分别为：貂蝉 191 年长安、甄宓 200 年冀州、孙尚香 209 年建业。这些是兼顾时代背景的游戏设定，并非她们确实在当地出仕的史实；武将属性也是游戏设定。孙尚香、貂蝉的寿命年份 240 是游戏规则所需的触发阈值，并非已知卒年。角色不会自动加入，须在对应城市搜索；登场顺序、空位和电脑搜索仍遵循现有规则。

孙尚香初始使用朱雀弓，甄宓和貂蝉使用白羽扇，三人配有锦鳞轻甲。白兵中，持弓将领可向同一行或列相距两格的敌军射击，地形与友军会遮挡，近身遇敌将仍单挑；双方均适用。为了平衡射程优势，远射伤害计算时将领战力和武器攻击分别按 55% 和 60% 计入，近战不折减；强弩和火矢仍作用于弓兵。扇的单挑命中沿用剑类，弓沿用长兵类；电脑之间直接结算的战争仍使用原版抽象规则，不逐格模拟远射或计算装备攻防。装备图标会随选择显示，人物立绘和动作仍使用角色所配置的素材，不会因换装自动改绘。

合并版的落日弓重量为 6、凤羽宝衣重量为 5；电脑在有扩展装备的城市会比较可负担装备的攻防、重量和购买条件，并可为合适的武将购入弓或扇。原版和旧「巾帼群英」维持原有购买规则及装备数值：旧版落日弓攻击 15，凤羽宝衣防御 12、重量 4、价格 420、人德要求 80。旧「群英新篇」存档的装备编号和拥有关系不变，读取后使用合并版的新数值和吕布技能；已经发布的自定义版本保留各自保存的装备数值与技能配置。编辑器添加模板时，若草稿已有同名、同类型和同图标的装备，也会沿用其已有数据。

包含新武器类别、防具或搜索优先设置的版本需要更新后的客户端与服务器；已发布的旧版本仍可读取。升级后如果玩家仍开着旧页面，请刷新后再选择新版本。

上传独立素材前先在管理页面输入管理员令牌。输入图片最多 8 MiB、1600 万像素，单个素材压缩后最多 1 MiB，单个版本最多引用 128 个不同素材、合计 16 MiB；版本 JSON 本身仍限 1 MiB。动作图须包含透明背景和可见图像。素材按内容哈希去重，存放在版本目录的 `assets/` 中，由玩家按需读取；上传后放弃草稿或发布失败时，未引用素材不会自动删除。游戏会在加载动作网格时统一各帧的角色比例、适度减少脚底留白，并为白兵和单挑移动使用行军帧；过宽的单行动作条会重新排列为多行，避免在纹理宽度有限的设备上缩小整张动作图。

原版数据没有内置人物关系记录；编辑器列出当前版本的关系，支持筛选及添加亲属、朋友、父子、兄弟、结义、君臣等关系，也可输入不超过 16 字的关系名称。关系在双方资料中使用相同名称，不自动改变招募、忠诚或战斗规则。新技能可组合固定的损兵、体力伤害、限制移动和粮草损失效果，不执行自定义代码。

出生年份和出生地用于人物资料，登场年份、地点和方式决定人物何时进入游戏。原有君主的开局位置不可修改；如果调整登场导致某城开局没有武将，该城会成为无主城。编辑器还可将某个势力的开局武将设为额外君主候选；玩家开局时可以选择这些候选，其所在势力由选中人物统领，原君主留在该势力。此功能不增加势力数量，旧版本与原版保留原有七位君主。

服务器默认允许读取已发布版本，**未配置管理员令牌时不允许发布**。令牌需为 32–256 位不含空格的可打印 ASCII 字符，请使用密码管理器生成的高强度随机值。首次启动或轮换令牌时，在当前终端输入令牌（输入不会回显）：

```bash
read -r -s GAME_ADMIN_TOKEN
export GAME_ADMIN_TOKEN
make up
```

Compose 会将令牌的 SHA-256 校验值保存在独立的 `game_admin_token` 持久卷中，文件仅允许所有者访问；不会把令牌原文写入该卷、浏览器或版本文件。随后容器重启或重建时，即使没有环境变量，也会继续使用已保存的令牌。该配置依赖同一 Compose 项目中的持久卷；迁移宿主机或更换项目时需迁移该卷或重新配置令牌。已有部署升级到此功能后，首次启动仍需提供原令牌一次，才能写入新的持久卷。

发布时在管理页面输入相同令牌；发布成功后输入框会清空。需要轮换令牌时，以新令牌重新执行上述命令；启动后旧令牌失效。使用同一可信持久令牌文件的运行中实例会在每次发布认证时读取最新校验值，轮换后的认证请求会使用新令牌；只使用进程内令牌的实例不会自动同步。启动时非空的 `GAME_ADMIN_TOKEN` 总是覆盖已保存的校验值，因此轮换后应协调所有实例的配置，避免其他实例重启时再次提供旧令牌。令牌文件和所在目录须由服务运行用户或 root 所有；文件不得允许其他用户访问，目录不得允许其他用户或用户组写入。无效的环境变量、不可写或损坏的令牌文件会禁用发布并记录错误，不会用错误令牌覆盖已保存的配置。首次启动时传入的环境变量仍可被具有 Docker 管理权限的人查看；若不再需要它，可在终端执行 `unset GAME_ADMIN_TOKEN`，然后重新执行 `make up`。

静态服务拒绝访问隐藏文件及指向 `.env` 配置的链接，`.env*` 也被排除在 Git 和 Docker 构建上下文之外。仍建议不要把真实令牌放在项目目录内。默认端口仅绑定本机；通过网络管理时，应使用 HTTPS 反向代理保护令牌。

玩家在标题画面选择「☰ 系统 → 游戏版本」，原版仍为默认；即使版本服务不可用，也可选择原版和内置版本。每次修改后发布都会创建不可覆盖的新版本编号，原版及各版本的普通、快捷、自动和中断战斗记录分别保存。管理页面可以导入、导出版本 JSON；含上传素材的版本会导出为包含素材的 JSON 包，在其他服务器导入时需先填写管理员令牌。未经修改的导入文件可用原编号恢复已发布版本。版本绑定当前基础数据，基础数据发生变化后需要先确认兼容性，不能直接当作新版加载。独立 Electron 离线包可选择原版及内置版本；服务器版本管理需要通过游戏服务器访问。

无法读取的单个版本会从列表中跳过，管理页面和游戏版本选择界面会提示数量，其他正常版本仍可使用。服务器日志会记录被跳过的版本编号，管理员可检查版本文件或从备份恢复；服务器不会自动删除或覆盖这些文件。整个版本目录无法访问时，列表仍会报告服务错误。

Compose 将已发布版本及其上传素材保存在 `game_versions` 卷，管理员令牌校验值保存在 `game_admin_token` 卷；`make down` 不会删除它们。删除对应卷会分别删除已发布版本及素材或令牌配置。迁移或备份版本时应保留整个版本目录及其 `assets/` 子目录。直接运行开发服务器时，版本默认保存在 `~/.local/share/threekindoms/versions`，可用 `GAME_VERSION_DIR` 指定其他可写目录；若也需要持久化令牌，设置 `GAME_ADMIN_TOKEN_FILE` 为静态服务目录之外的绝对文件路径。未设置该路径时，直接运行的服务器仅在当前进程内使用令牌。

## 测试

浏览器测试用 Playwright 驱动本机 Chrome 的无头模式，需要先装 Playwright（`npm i -g playwright`）和 Google Chrome。

```bash
node --test hd2d-mvp/tests/artcoverage.test.mjs                  # 单个测试文件
node --test --test-concurrency=1 'hd2d-mvp/tests/*.test.mjs'     # 全部测试（较慢，war.test 约 10 分钟）
python3 hd2d-mvp/tests/scenario_server_test.py                  # 游戏版本发布接口与认证
```

## 打包桌面版

需要 `cwebp`（macOS 上用 `brew install webp` 安装）。

```bash
npm --prefix hd2d-mvp/desktop run dist:mac    # macOS dmg（arm64 与 x64）
npm --prefix hd2d-mvp/desktop run dist:win    # Windows x64 zip
npm --prefix hd2d-mvp/desktop run dist:dir    # 只出 macOS 的 .app 目录，最快
npm --prefix hd2d-mvp/desktop start           # 直接用 Electron 运行游戏（需要先执行一次 build-app）
```

这几个命令都会先运行 `build-app.mjs`，把游戏快照到 `hd2d-mvp/desktop/app/`，产物放在 `hd2d-mvp/desktop/release/`。
