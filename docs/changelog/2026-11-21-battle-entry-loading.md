# 战斗开场、地表贴图和音乐加载

- 扩展战场按地图格数控制合成贴图的像素量。3D 战场主贴图最多约 310 万像素，手机平面战场最多约 210 万像素。城墙模型、树木图集和武将动作继续使用原素材。战场格数、路线、地形规则和中断记录格式保持原样。
- 14 张重复铺用的地表与岩壁材质改用轻量 WebP。地表规格从 512×512 降至 384×384，岩壁宽度从 1024 降至 768，保留原长宽比。素材损坏或读取超时可回退。每场按季节和显示模式读取所需地表、积雪或装饰，整张历史手绘地图仅用于原版平面战场。
- 战场贴图和行军素材在画面淡出期间并行加载。战斗曲从确定出阵或收到来袭提示时开始后台读取，进入战斗后复用同一次下载和解码。慢网或曲目错误时仍可照常布阵，当前曲库和备用曲目沿用原规则。

## 开场实测

使用同一台 Mac、本机开发服务器和无头 Chrome。兖州之战双方各三将，每种模式各用三个全新浏览器上下文，取开始切入战斗至「布阵完成」可用的中位数。手机使用 844×390 触控视口模拟。测量静音，资源体积统计地表及行军素材，包含同期读取的共用白兵地表素材。

| 战场 | 进场时间 | 读取的地图与行军素材 |
| --- | --- | --- |
| 君主列传桌面 3D，48×32 格 | 1.87 秒 → 1.63 秒 | 3.22 MiB → 2.62 MiB |
| 君主列传手机平面，48×32 格 | 1.13 秒 → 0.97 秒 | 3.22 MiB → 2.65 MiB |
| 原版桌面 3D，32×19 格 | 1.52 秒 → 1.46 秒 | 3.79 MiB → 2.59 MiB |

48×32 格样本的 3D 主地表贴图从 2912×2016 降到 2080×1440，像素量减少约 49%。手机地表合成中位数从 502 毫秒降到 235 毫秒。另用浏览器挂起战斗曲请求，验证布阵完成后同一请求仍可解码和开始播放。
